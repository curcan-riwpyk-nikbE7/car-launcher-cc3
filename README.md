# Car Launcher — лаунчер для Android-магнитолы (стиль TEYES CC3)

Тёмный ландшафтный лаунчер для головных устройств. Kotlin + Jetpack Compose,
`minSdk 23` (Android 6.0), `targetSdk 30`.

![preview](preview.png)

## Готовые APK

| Файл | Размер | Для чего |
|---|---|---|
| `KINGSAID.apk` | **1.4 МБ** | Подписан, ужат R8 — ставить на магнитолу |
| `CarLauncher-debug.apk` | 17 МБ | Для отладки |

Оба собраны и проверены: `aapt2` подтверждает `minSdk 23`, `targetSdk 30`
и наличие `intent-filter` с `category.HOME`. Подпись валидна (`apksigner verify`).

## Экран

**Слева — сайдбар:** часы, индикатор сети 4G, пульсирующий градиентный «орб»
голосового ассистента, настройки, все приложения. В левом нижнем углу —
крупная градиентная кнопка навигации.

**Сверху — статус-бар:** Wi-Fi, дата, микрофон, Bluetooth, погода, громкость,
кнопка раскрытия системной шторки (через рефлексию `StatusBarManager`).

**Медиа-карточка** с фирменным градиентом синий → фиолетовый → розовый:
название трека и исполнитель читаются из реальной `MediaSession`, обложка
альбома проступает сквозь градиент, эквалайзер анимируется только когда играет
музыка. Кнопки назад / плей-пауза / вперёд.

**Карточка авто:** скорость с GPS, рендер машины в неоне, круглые кнопки
климата и света.

**Карточка «Приложения»:** 4 избранных + кнопка Add. Тап по пустой ячейке или
долгое нажатие на занятую — выбор любого установленного приложения.

**Карточка радио:** название станции, перемотка и градиентный блок с волной.

## Погода

В статус-баре показывается настоящая температура с иконкой состояния
(ясно, облачно, дождь, снег, гроза, туман) — раньше там было
захардкоженное «18°».

Источник — **Open-Meteo**. Выбран потому, что работает **без ключа API
и регистрации**: для приложения, которое ставят сайдлоадом на магнитолу,
это критично — не нужно вшивать чужой токен в APK.

Координаты берутся из последней известной позиции (`getLastKnownLocation`),
отдельный запрос к GPS не делается — разрешение уже есть ради спидометра,
а ждать фикс спутников ради погоды незачем.

Ответ кэшируется на 15 минут, ключ обновления привязан к тику часов.
Если сети нет, разрешение на геолокацию не выдано или запрос упал —
блок погоды просто **не отображается**, вместо того чтобы показывать
устаревшие или выдуманные данные.

## Приложение прямо в карточке спидометра

Три режима на выбор — удержание на карточке открывает диалог.

**1. «Прямо в карточке» — то, что и требовалось.**
Приложение запускается в плавающем окне, координаты которого равны
границам карточки. Работает через публичный `ActivityOptions.setLaunchBounds`
(API 24+): карточка сообщает свою позицию через `onGloballyPositioned`,
и система рисует YouTube или Карты ровно в этом прямоугольнике.

Условие одно — включённый режим freeform-окон. **Root не нужен**,
достаточно один раз выполнить:

```
adb shell settings put global enable_freeform_support 1
```

На части ГУ он включён производителем изначально. Тем же способом
работает известный лаунчер Taskbar — подход проверенный.

**2. «Открыть рядом»** — разделённый экран, лаунчер слева, приложение справа.

**3. «На весь экран»** — обычный запуск.

Если freeform недоступен, в диалоге показывается подсказка с командой,
а запуск честно откатывается на полноэкранный — нажатие не остаётся
без результата.

### Чего действительно нельзя

Встроить чужое приложение **внутрь своего окна** (как `ActivityView`)
нельзя без системных привилегий: нужны разрешения `ACTIVITY_EMBEDDING`
или `INTERNAL_SYSTEM_WINDOW` уровня `signature|privileged`, плюс само
приложение должно разрешить встраивание флагом `allowEmbedded`.
YouTube его не выставляет. Именно поэтому выбран путь плавающего окна:
визуально результат тот же, а прав хватает обычному APK.

## Адаптация под экран головного устройства

![720p](screen720.png)

Раньше все размеры были жёстко прописаны в dp — панель 108 dp, кнопка
навигации 104 dp, орб 88 dp. На разных ГУ это ломалось.

**Почему.** У магнитол с экраном 1280×720 плотность бывает разной.
При 160 dpi это 1280×720 dp — очень просторно, интерфейс выглядит мелким.
При 320 dpi те же 1280×720 пикселей дают всего **640×360 dp** — панель
на 108 dp съедала бы шестую часть ширины, а кнопка навигации уезжала
за нижний край.

**Что сделано.** Корневой контейнер обёрнут в `BoxWithConstraints`,
размеры считаются от фактически доступного места и раздаются через
`CompositionLocal`:

| Элемент | Формула | Пределы |
|---|---|---|
| Ширина панели | 9.5% ширины | 72–120 dp |
| Кнопка навигации | 17% высоты | 64–110 dp |
| Кольцо ассистента | 14.5% высоты | 48–92 dp |
| Иконки панели | 9.5% высоты | 38–58 dp |
| Размер шрифта скорости | 8.5% высоты | 28–52 sp |
| Статус-бар | 6.2% высоты | 26–42 dp |

Пределы нужны, чтобы на очень большом экране элементы не раздувались,
а на очень маленьком оставались нажимаемыми.

**Проверка вместимости панели** (часы + орб + 3 иконки + отступы + кнопка):

| Экран | Панель занимает | Доступно |
|---|---|---|
| 1280×720 @160 dpi | 517 dp | 720 dp |
| 1280×720 @213 dpi | 440 dp | 540 dp |
| 1280×720 @240 dpi | 395 dp | 480 dp |
| 1280×720 @320 dpi | 321 dp | 360 dp |
| 1024×600 @160 dpi | 484 dp | 600 dp |

Во всех случаях помещается с запасом.

## Большое обновление: 10 доработок

**Плеер**
- Полоса прогресса с перемоткой в развёрнутом плеере. Позиция от системы
  приходит редко, поэтому между обновлениями докручивается локально по
  часам — иначе полоса дёргалась бы рывками раз в несколько секунд.
  Если плеер не отдаёт `ACTION_SEEK_TO`, ползунок блокируется с пояснением.
- Свайп вниз закрывает развёрнутые карточки — привычнее, чем целиться в крестик.

**Развёрнутые карточки**
- Удержание на радио — крупная частота и большие кнопки.
- Удержание на карточке авто — спидометр и трип-компьютер.

**Трип-компьютер** — пробег, средняя и максимальная скорость, время в пути.
Считается по GPS, который уже работает ради спидометра. Точки медленнее
2 км/ч игнорируются, скачки больше километра за тик отбрасываются как
потеря сигнала — иначе на стоянке накрутились бы лишние километры.

**Ночной режим** — экран притухает после заката. Время рассвета и заката
берётся по сезону без обращения к сети.

**Свои обои** — картинка из галереи. Копируется в файлы приложения и
ужимается до 1600 px: URI из системного пикера живёт недолго, а
полноразмерное фото с телефона съело бы память слабого ГУ.

**Вторая страница приложений** — 10 ячеек вместо 5, листаются свайпом,
внизу точки-индикаторы.

**Автозапуск музыки по Bluetooth** — слушаем именно профиль A2DP, а не общее
подключение, иначе музыка стартовала бы при коннекте часов или брелка.
Пауза 2.5 секунды, чтобы телефон успел договорить рукопожатие.

**Локализация** — 63 строки вынесены в `strings.xml`, добавлен английский
перевод в `values-en`. Раньше весь текст был захардкожен в Kotlin.

## Полный экран, тёмно-синяя гамма, большой плеер

![player](player_expanded.png)

**Полноэкранный режим.** `WindowCompat.setDecorFitsSystemWindows(window, false)` —
лаунчер рисует под системными барами и занимает экран целиком.

**Статус-бар вынесен наверх** отдельной строкой во всю ширину, над панелью
и карточками. Слева время крупно, справа Bluetooth, микрофон, Wi-Fi, сеть,
погода и громкость. Раньше он был зажат в правом углу колонки контента.

**Единая тёмно-синяя палитра.** Из темы по умолчанию убраны фиолетовый и
чёрный — остались оттенки синего от `#12213F` до `#060E1B`, акцент
голубой `#29B6F6`. Тема переименована в **Deep Blue**.

**Развёрнутый плеер.** Удержание на медиа-карточке открывает окно поверх
экрана: крупная обложка, название, эквалайзер и большие кнопки. Обложка
дублируется размытым фоном, чтобы окно принимало цвет альбома.
Закрывается крестиком или тапом по затемнению.

## Защита от тупиковых ситуаций

![fixes](fixes.png)

Четыре проблемы, которые ломали базовые сценарии.

**1. Баннер «назначьте лаунчер».** Раньше человек ставил APK, жал «Домой»
и попадал в старый лаунчер, не понимая почему. Теперь при запуске
проверяется `resolveActivity` для `CATEGORY_HOME`, и если главный не мы —
показывается баннер с кнопкой перехода в системный выбор. Проверка
повторяется на каждом `ON_RESUME`, поэтому баннер исчезает сразу после
назначения. Крестик прячет его навсегда.

Системный экран открывается по цепочке: `MANAGE_DEFAULT_APPS_SETTINGS`
на Android 10+, затем `HOME_SETTINGS`, затем общие настройки — на разных
прошивках ГУ доступны разные.

**2. Кнопка «Назад» на экране приложений.** Её не было вообще, а immersive-режим
прячет системные кнопки — из списка было физически не выйти.

**3. Автообновление списка.** `PackageChangeEffect` слушает `PACKAGE_ADDED`
и `PACKAGE_REMOVED`. Промежуточное событие с `EXTRA_REPLACING` пропускается,
иначе при обновлении приложения список перестраивался бы дважды.

**4. Действия по долгому тапу:** в избранное, «О приложении», удалить.
Системные приложения удалить нельзя — для них вместо `ACTION_DELETE`
открывается экран с кнопкой «Отключить».

**Плюс пустые состояния.** Раньше при загрузке или пустом поиске был просто
чёрный экран. Теперь: спиннер «Загрузка приложений…», «Ничего не найдено»
с текстом запроса, «Приложения не найдены» если система ещё не отдала список.

## Боковая панель

![panel](panel.png)

Панель переделана по эталонному скриншоту — прежняя была слишком узкой
и мелкой для управления на ходу.

**Что изменилось** (пропорции сняты замером с оригинала):

| Элемент | Было | Стало |
|---|---|---|
| Ширина панели | 76 dp | **108 dp** |
| Кольцо ассистента | 44 dp | **88 dp** со свечением |
| Иконки | 40 dp | **56 dp** |

градиент внутри кольца вращается.

## Экран настроек

![settings](settings.png)

Оформлен в стиле штатного меню магнитолы: **вкладки-пилюли сверху,
крупные плитки снизу**. У активной вкладки градиентная рамка
зелёный → синий, как в оригинальном интерфейсе ГУ.

Плитки высокие намеренно — в них удобно попадать пальцем на ходу,
не целясь в мелкие строчки списка.

| Вкладка | Что внутри |
|---|---|
| **Оформление** | 6 тем плитками с живым мини-макетом раскладки |
| **Жесты** | Вкл/выкл, порог смены трека, шаг громкости, вибро — ползунки прямо в плитках |
| **Приложения** | 5 ячеек: иконка, что назначено, кнопка «Очистить» |
| **Экран** | Не гасить экран, полный экран, спидометр — переключатели в плитках |
| **Система** | Доступ к уведомлениям, виджеты, сброс с подтверждением, версия |

Настройки не просто сохраняются, а реально меняют поведение: выключенные
жесты отключают перехват касаний целиком, ползунки подставляются в детектор,
переключатели дёргают системные флаги окна.

Сброс сделан в два шага — первый тап меняет надпись на «Точно сбросить?»,
второй выполняет. Отдельный диалог для этого не нужен.

## Семь тем оформления

![themes](themes.png)

Тема меняет не только палитру, а **раскладку экрана, форму карточек,
стиль спидометра, часов и шрифт**.

![aurora](theme_aurora.png)

*Aurora Flow — сделана по присланному скриншоту: цвета сняты пипеткой,
раскладка `GridDock` с сеткой приложений прямо на фоне и доком внизу.*

| Тема | Панель | Спидометр | Часы | Особенности |
|---|---|---|---|---|
| **Neon Drive** | слева | крупные цифры | цифровые + 4G | синий→фиолет, неоновая кромка медиа |
| **Deep Blue** | слева | крупные цифры | цифровые + 4G | единая тёмно-синяя гамма, фото авто |
| **Aurora Flow** | **док снизу** | тонкие цифры | **крупные справа** | сетка приложений на фоне, FM-виджет, компас, градиент зелёный→фиолет |
| **Tesla Mono** | док снизу | тонкие цифры | компактные | светлая, без фото авто, минимум декора |
| **Cyber Grid** | справа | аналоговое кольцо | компактные | острые углы (4 dp), моноширинный шрифт, ПОДПИСИ КАПСОМ |
| **Retro Amber** | сверху | аналоговое кольцо | **стрелочные** | янтарь на тёмном, капс |
| **Sport Carbon** | слева | крупные цифры | цифровые | карбон, красный акцент, тонкие рамки |

Открывается иконкой палитры на панели. Выбор сохраняется и применяется
мгновенно — Activity не перезапускается.

### Как это устроено

Вся тема описана одной `data class ThemeSpec`: цвета, радиусы скруглений,
толщина рамок, тип раскладки, стиль спидометра и часов. Добавить шестую тему —
это дописать один объект в список `AllThemes`, экраны трогать не нужно.

Раскладка выбирается в `HomeScreen` через `when (spec.layout)`: панель может
быть колонкой слева/справа либо горизонтальным доком сверху/снизу. Сами
карточки при этом переиспользуются — меняется только контейнер.

Чтобы не переписывать десяток экранов под новую систему, в `ThemeCompat.kt`
лежат `@Composable`-геттеры со старыми именами (`TextPrimary`, `CardBg`,
`Cyan` и т.д.), которые теперь читают активную тему из `LocalThemeSpec`.
Существующий код перекрашивается сам.

## Жесты по экрану

![gestures](gestures.png)

| Жест | Действие |
|---|---|
| Свайп **влево** | Следующий трек |
| Свайп **вправо** | Предыдущий трек |
| Тянуть **вверх** | Громче |
| Тянуть **вниз** | Тише |

Работают в любом месте главного экрана, поверх всех карточек.

**Ось фиксируется по первому движению.** Как только палец сдвинулся на 18 dp
в одну сторону с перевесом в 1.3 раза, жест до конца считается либо
горизонтальным, либо вертикальным. Иначе «косой» свайп за рулём менял бы
и трек, и громкость одновременно.

**Обычные нажатия не сломались.** События перехватываются только после того,
как жест распознан (`change.consume()` вызывается лишь при `axis != 0`), —
поэтому тап по карточке или кнопке работает как раньше.

**Громкость меняется пошагово, пока тянешь:** каждые 40 dp — один шаг
системной громкости. Трек переключается один раз за свайп, порог 80 dp,
чтобы случайное касание не перематывало музыку.

Системную шторку громкости мы намеренно **не** показываем
(`adjustStreamVolume` с флагом `0`) — вместо неё рисуется своя подсказка
в стиле лаунчера, которая гаснет через 900 мс. Каждое срабатывание
подтверждается вибрацией.

## Как это работает под капотом

**Медиаплеер.** Название трека читается через `MediaSessionManager`, что
требует доступа к уведомлениям — в манифесте объявлен пустой
`NotificationListenerService`. Если доступ не выдан, карточка покажет заглушку,
а тап по названию откроет нужный экран настроек. **Управление** (плей/пауза,
трек вперёд/назад) работает всегда, без каких-либо разрешений: оно идёт через
`AudioManager.dispatchMediaKeyEvent`, который понимают все плееры, включая
штатные приложения магнитолы.

**Пакеты Яндекса.** Яндекс Музыка — это `ru.yandex.music` (не `com.yandex.music`,
как я написал в первой версии), Навигатор — `ru.yandex.yandexnavi`, Карты —
`ru.yandex.yandexmaps`. В список навигации добавлен ещё и 2ГИС
(`ru.dublgis.dgismobile`).

**Запуск приложений ГУ.** Кнопки не привязаны к одному пакету, а перебирают
список кандидатов под разные прошивки — например радио пробует
`com.hzbhd.radio`, `com.microntek.radio`, `com.syu.radio`, `com.ts.fmradio`
и другие. Не нашлось — показывается тост с подсказкой назначить вручную.

**Скорость.** Берётся из `Location.speed` (м/с → км/ч). Значения ниже 2 км/ч
отсекаются, иначе на стоянке цифра прыгает из-за дрейфа GPS. Без разрешения
на геолокацию просто останется 0 — карточка это переживёт.

## Сборка

```bash
# Android Studio: File → Open → папка CarLauncher
./gradlew assembleRelease
```

APK появится в `app/build/outputs/apk/release/app-release.apk`.

> В `gradle.properties` стоит `kotlin.compiler.execution.strategy=in-process`
> и уменьшенный heap — это нужно было для сборки на машине с 2 ГБ ОЗУ.
> На обычном компьютере эти строки можно убрать, сборка станет быстрее.

Проект подписан тестовым ключом `carlauncher.jks` (пароль `carlauncher`).
Для своей сборки сделайте свой ключ:
```bash
keytool -genkeypair -keystore my.jks -alias my -keyalg RSA -validity 10000
```

## Установка на магнитолу

```bash
adb connect 192.168.0.x:5555      # или по USB
adb install -r KINGSAID.apk
```

Затем **Настройки → Приложения → По умолчанию → Главный экран → Car Launcher**,
либо нажмите «Домой» и выберите Car Launcher с опцией «Всегда».

После установки стоит выдать два доступа:
- **Уведомления** (`Настройки → Доступ к уведомлениям`) — чтобы карточка
  показывала название трека
- **Геолокация** — для спидометра

Откат, если что-то пошло не так:
```bash
adb shell cmd package set-home-activity <пакет.старого.лаунчера>
```

## Заметки по совместимости

- `targetSdk = 30` намеренно: на 31+ многие прошивки ГУ ломают запуск сторонних
  intent-ов из-за требований к `PendingIntent.FLAG_IMMUTABLE`. Lint-правило
  `ExpiredTargetSdkVersion` отключено — оно относится к публикации в Google Play.
- `QUERY_ALL_PACKAGES` нужен для списка приложений на Android 11+.
- Ориентация `sensorLandscape`. Для портретного экрана поменяйте её в манифесте
  и `Row` на `Column` в `HomeScreen.kt`.
- Картинка авто — сгенерированный WebP на 35 КБ. Заменить: положите свой файл
  в `res/drawable-nodpi/car_rear.webp`.
